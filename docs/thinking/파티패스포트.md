## 1. 한 줄 — 파티 "중"의 어색함, "후"의 흐지부지

**파티 참가자가 캐릭터를 고르고, 서로의 QR을 태그해 "만난 사람 수"를 쌓으면 캐릭터가 새싹→잎→꽃으로 자라고 증표를 받으며,
파티가 끝나면 만난 사람 중 다시 만나고 싶은 사람을 골라 서로 고른 쌍만 공개하는 웹.**

**현장 문제**: 축제·오프사이트·생일파티에서 아는 사람끼리만 논다. 처음 보는 사람에게 말 걸 계기가 없고, 파티가 끝나면 누구를 만났는지도, 누가 다시 보고 싶어 하는지도 남지 않는다.

### 흐름 (전 · 중 · 후)

| 순간 | 동작 |
|---|---|
| 전 | 호스트 `파티 만들기` (파티 이름 · **캐릭터 · 관심사**) → 호스트도 참가자 1번, 초대 링크(= 호스트 코드가 실린 URL) |
| 중 | 참가자 링크로 `참여하기` (이름 · **캐릭터 · 관심사**) → `참여 완료` + 초대자와 태그 → `만난 사람 1명` · `첫 만남` · **캐릭터 새싹→잎**. 이후 남의 QR을 폰 카메라로 찍거나 `코드로 태그` → 둘 다 +1 → 진행률 · 증표 · 성장 · 미션 상대(공통 관심사 표시) |
| 후 | 호스트 `파티 종료` → 만난 사람 중 `다시 만나고 싶은 사람` 체크 + **다시 만나고 싶은 정도(☕ 가볍게 / 🙌 반가웠어요 / 💫 꼭 다시)** → `선택 제출` → **서로 선택된 사람만** 양쪽 정도(연락처 교환 파티면 **연락처**까지)와 함께 표시 → `내 증표함` → `다음 파티 만들기` |

### "만남"의 정의 — ⬜ 결정 필요

**현재 구현**: 초대 링크(`?from=초대자코드`)로 참여하면 서버가 초대자와 **자동으로** 상호 태그한다. 그 외 만남은 QR(=URL) 또는 `코드로 태그` 4자리 입력으로 기록된다. 제출 시나리오·기획안도 이 동작을 근거로 쓰여 있다.

리뷰(엔지니어·투자자)의 지적: 카톡으로 링크를 받아 집에서 참여해도 "만남"이 된다 — "이 파티에서 실제로 만난 사람"이라는 데이터 정의가 약하다.

| 선택지 | 내용 | 비용 |
|---|---|---|
| A. 유지 | 자동 태그 그대로. 기획안에 "초대 링크 교환 = 만남으로 간주"를 명시하고 한계를 솔직히 적는다 | 0 |
| B. 확인 버튼 | 참여 직후 "초대한 OO님을 지금 만났나요?" → `지금 만났어요` 클릭 시에만 기록. 3단계에 클릭 1번 추가 | 서버 `join` 자동 태그 제거 + 프론트 버튼 1개 + 시나리오·기획안 2곳 수정 |

권고는 B(리뷰 방어). 시간이 없으면 A + 솔직한 문장.

| 키 | 표시 | 이름 |
|---|---|---|
| FOX | 🦊 | 여우 |
| FROG | 🐸 | 개구리 |
| PANDA | 🐼 | 판다 |
| CHICK | 🐥 | 병아리 |

| LION | 🦁 | 사자 |

보이는 곳: 내 패스포트 카드(크게) · 만난 사람 목록 · 미션 카드 · 결과 화면 · 내 증표함. 일러스트가 나오면 이모지를 교체(디자이너 가이드 04).

### 새싹 성장 (신규) — 피크민의 잎→봉오리→꽃

캐릭터 옆에 성장 단계가 붙는다. **만난 사람 수**로 결정, 저장 없이 계산.

| 단계 | 조건 | 표시 |
|---|---|---|
| 새싹 | 0명 | 🌱 |
| 잎 | 1~2명 | 🌿 |
| 꽃 | 3명 이상 | 🌸 |

3단계 시나리오에서 참여 직후 만난 사람 1명 → **새싹이 잎으로 바뀌는 게 화면에 보인다**(A4 디테일 + "숫자가 오르면 뭔가 변한다"는 동기).

### 관심사 태그 (신규) — 말 걸 거리

고정 12개 중 **최대 3개, 선택 사항**: `게임 · 러닝 · 영화 · 음악 · 여행 · 요리 · 독서 · 그림 · 축구 · 반려동물 · 카페 · 개발`.
보이는 곳: 내 카드 · 만난 사람 · **미션 카드에 "공통 관심사: 러닝 — 이걸로 말 걸어 보세요"** · 결과 화면 서로 선택된 사람 카드. 자유 입력은 받지 않는다(욕설·개인정보·A4 리스크).

### 증표 (발급 조건 고정)

| 증표 | 조건 |
|---|---|
| 첫 만남 | 1명 |
| 아이스브레이커 | 3명 |
| 파티 피플 | 참가자 절반 이상 |
| 파티 마스터 | 전원 |
| 미션 완료 | 지정된 미션 상대와 만남 |
| 재회 | 서로 선택된 사람 1명 이상 |

분모 = 조회 시점의 현재 참가자 수. 증표함(브라우저 저장)에 한 번 들어간 증표는 취소되지 않는다.

### 1:1 미션 (현재 구현)

**미션 상대 = 나보다 바로 앞에 참여한 사람**, 호스트(1번)의 상대는 2번. 참여 시점에 서버가 확정 저장하므로 화면에서 바뀌지 않는다. 미션 카드에 상대의 캐릭터·관심사·공통 관심사를 함께 보여준다.

## 2. 초대/동반 참여 없이는 안 되는 이유 (B3)

남의 코드가 있어야 숫자가 오르고 캐릭터가 자란다. 혼자면 0, 새싹, 증표 0, 미션 없음. **전원이 동시에 각자** 진행한다.

**성장 루프**: 호스트 → 초대 링크 → 참여자 N명 → 참여자도 자기 코드가 실린 링크(= 내 QR)를 공유 → 데려온 사람과 둘 다 +1 → 파티 후 `다음 파티 만들기`로 참여자가 다음 호스트가 된다. 공유 버튼이 아니라 **숫자가 오르는 유일한 경로**다.

## 3. 대체재로 안 되는 이유 · 우리가 이기는 이유 (C3)

| 대체재 | 못 하는 지점 |
|---|---|
| 카카오톡 단톡방 · 구글폼 | "이 파티에서 만난 사람" 데이터가 없다. 상호 선택은 사람이 집계해야 해서 짝사랑이 집계자에게 노출된다 |
| 인스타 맞팔 | 파티 밖 관계까지 섞인다. 진행률·증표·성장·"다시 만나고 싶은 사람" 0 |
| **Event Passport PRO** (네이티브 앱) | 컨퍼런스·전시 **조직자용**: 조직자 계정 + 사전 세팅 + 참가자 전원 앱 설치. 개인 QR·스탬프·진행도는 있지만 **만남 기록에서 끝난다 — 파티 후 상호 선택이 없다** |
| **Bumpt** (행사 네트워킹 게임화) | 퀘스트·수집품·어워드. 조직자 세팅형·영어권. **서로 고른 쌍만 공개하는 단계가 없다** |
| 종이 스탬프 랠리 | 부스용이지 사람용이 아니다 |

> ⬜ 제출 전 EPP 스토어 페이지·Bumpt 사이트에서 **설명 문구·요금**을 확인하고 그대로 인용. 리뷰 시점 확인값: EPP 무료 50명, Pro $100/월(200명). **다운로드 수 같은 검증 안 된 숫자는 쓰지 않는다.**

**① 결말이 다르다: 비밀 상호 선택 + 정도.** EPP·Bumpt는 "몇 명 만났나"에서 끝난다. 우리는 "누구와, 얼마나 다시 만나고 싶은가"를 **서로 고른 쌍에게만** 돌려준다. 단독 선택(과 그 정도)은 **서버 밖으로 나가지 않는다** — API가 상호인 것만 반환하고, 목록 조회 엔드포인트가 없다(13절).
**② 세그먼트가 다르다: 세팅 0 · 설치 0 · 계정 0.** 링크 하나, 이름·캐릭터만. **해자가 아니라 우위**라고 쓴다 — 방어는 ①과 참여자→다음 호스트 루프.
**③ 캐릭터·성장·관심사는 차별점이 아니라 동기 장치다.** 기획안에 "차별점"으로 쓰지 말고 A4(완성도)·B3(말 걸 이유) 근거로만 쓴다.

## 4. 다시 올 이유 (B4)

- 증표·캐릭터는 파티가 끝나도 **`내 증표함`(브라우저 저장)에 남고 다음 파티에서 누적**. 기기 간 이전 없음(문서에 "계정으로 누적" 금지).
- **트리거 시점**: 호스트가 `파티 종료`를 누른 직후 선택 화면 → 제출 → 결과. 상대가 아직 안 골랐으면 "상대방도 선택을 제출하면 이곳에 나타납니다" — 다시 들어올 이유.
- **다시 만나고 싶은 정도**는 서로 선택된 경우에만 양쪽 것이 공개된다(☕/🙌/💫). 단독 선택의 정도는 영원히 비공개.
- 결과 화면 `다음 파티 만들기`.
- **연락처 교환 파티**: 선택 제출 시 남긴 연락처(카카오 오픈채팅 링크·인스타)가 서로 선택된 상대에게만 열린다 — 파티 후 실제로 다시 만나는 경로.

> 화면·기획안에서 **"호감도" 대신 "다시 만나고 싶은 정도"** 를 쓴다 — 데이팅 앱 오독(게이트 ×0.85) 방지.

## 7. 수익 모델 (C1) — 단일가 9,900원, 유료 조건 2개

| 요소 | 값 |
|---|---|
| 지불 주체 · 시점 | **호스트 · 파티 생성 시** |
| 금액 | **파티당 9,900원** — 다음 중 하나면 유료: **21명 이상** 또는 **`연락처 교환` 옵션을 켬**. 그 외 무료 |
| 화면 문구 | 생성 모달·홈 하단 `20명까지 무료 / 21명 이상 또는 연락처 교환 시 9,900원` + 토글·인원에 따라 `이 파티: 무료 / 9,900원` 동적 표시 (결제 연동 없음) |
| 근거 | 동아리 회비·회식 예산의 2~3%, 인터뷰 3명 지불 의향(02-기획안). 연락처 교환은 Whova류 행사 도구의 유료 기능이 선례 |

**연락처 교환 옵션(신규)** — 호스트가 켜면 참가자는 파티 종료 후 `다시 만나고 싶은 사람` 제출 폼에서 `내 연락처 (선택)`(카카오 오픈채팅 링크·인스타 @아이디)를 남기고, **서로 선택된 쌍에게만** 공개된다. 옵션이 꺼진 파티엔 입력칸 자체가 없다. 참가자는 항상 무료.

**기각한 안 — 참가자 크레딧(매칭 시 연락처 블러 → 크레딧으로 열기)**: C1은 +0.2 오르지만 "호감 → 매칭 → 유료 연락처 열기"가 데이팅 앱 수익 구조 그대로라 게이트 ×0.85(−1.0) 리스크가 더 크고, 오프사이트·MT에서 동료 연락처를 돈 내고 여는 건 제품 논리가 안 선다. 8절 확장 경로에만 남긴다.

⬜ 무료 인원을 50명으로 올리면 서버 상수 1줄 + 화면 문구 2곳 + 기획안 81·83행을 **동시에** 바꾼다(문구가 곧 C1 evidence).

## 8. 시장 규모 (C2)

상향식 계산은 [02-기획안 8절](../submission/02-기획안-8000자.md)이 기준(1.13억 + 4천만). 이 문서에서는 중복 계산하지 않는다 — 숫자가 두 벌이면 갈라진다. ⬜ 「가정」 표기와 대학생 수 출처만 확인.

**확장 경로(미구현, C1 근거 아님)**: 솔로파티 세그먼트에서 **참가자 크레딧(매칭 시 연락처 열기)** 실험 · 축제 스폰서 증표 · 행사 대행사 B2B.

## 13. 저장소 · 보안 — 서버가 강제하는 것 / 못 하는 것

Spring Boot 3 + PostgreSQL(`ddl-auto: update`), 인증 없음. 참가자 ID(UUID)가 사실상 **본인 토큰**이다. 상세·API·수정안은 [backend PRD](../prd/backend.md).

| 서버가 **강제**하는 것 | 서버가 **못 하는** 것(솔직하게) |
|---|---|
| 만남은 파티 안에서 **상대 4자리 코드**가 있어야 생성(코드는 본인 화면·QR에만) | 코드를 받은 뒤 실제 대화했는지는 검증 못 함(자기 신고). 초대 링크 자동 태그는 원격 참여도 만남으로 기록 |
| 자기 자신 태그 불가, 같은 쌍 중복 불가(정렬 + unique) | 종료된 파티에도 태그 가능(⬜ 종료 후 거부 3줄) |
| 상호 선택: API가 **서로 고른 쌍만** 반환. 단독 선택과 그 정도는 응답에 절대 포함되지 않고 목록 API가 없다 → 개발자도 DB를 직접 열지 않는 한 짝사랑을 못 본다 | **남의 participantId를 알면 그 사람 대신 선택 제출·태그가 가능** — 만난 사람 응답에 ID가 실려 있어 실제로 알 수 있다. **수정 필수**: 응답에서 남의 `participantId` 제거, 선택은 `tagCode`로 지정 |
| 코드 유일성, 이름 길이 검증 | 증표함·세션은 브라우저 저장 — 폰을 바꾸면 이어지지 않음 |
| 🆕 연락처는 **옵션 켜진 파티 · 상호 선택된 쌍**에게만 응답. 단독 선택자·만난 사람 목록·패스포트에는 절대 없음 | 연락처 형식(오픈채팅 링크·인스타)은 검증하지 않음. 남의 ID 노출 수정(🔴) 전에는 선택 위조로 연락처 탈취 가능 → **선행 필수** |

> 자가 채점표는 넣지 않는다. 판정은 별도 세션에서 [personas](../personas/) 3종 검증.
> ⬜ 남은 것: B1/B2 실제 인용 확인 · EPP/Bumpt 문구 재확인 · 미결 2개 결정 · 보안 수정(6번) · 3단계 Playwright 검증.
