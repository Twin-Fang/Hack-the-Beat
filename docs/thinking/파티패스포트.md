# 확정 — 파티 패스포트 (QR 태그 수집 · 증표 · 파티 후 상호 선택)

> **확정.** 피크민이 걸음 수라면 이건 **파티에서 말 건 사람 수**다.
> "증표 받으려면 3명은 만나야 해"가 낯선 사람에게 말 걸 핑계가 된다.

> **v3 — 3 페르소나 리뷰(창업가 6.4 · 엔지니어 7.2 · 투자자 3.8) 반영.** 바뀐 곳:
> ① "초대 링크 참여 = 만남" 자동 태그 **삭제** → 참여 후 `지금 만났어요` 명시적 확인 (3단계 안에 그대로 남음)
> ② 익명 인증(로그인 UI 없음) 도입 → 상호 선택 규칙이 **실제로** 자기 선택만·한 번만 쓰게 강제. 만남 기록도 상대 코드가 있어야만 생성
> ③ C3: Event Passport PRO "다운로드 10+" **삭제(사실 오류)**. 결말(비밀 상호 선택)로 차별화, "설치 0"은 우위이지 해자 아님으로 명시
> ④ C1: 50명까지 무료 / 51명부터 파티당 9,900원 — 직접 경쟁사 요금을 기준점으로
> ⑤ C4: 서버 원가 기준 마진만 주장, 결제 수수료 별도 표기
> 구현 명세는 [docs/prd/frontend.md](../prd/frontend.md) · [docs/prd/backend.md](../prd/backend.md).

## 1. 한 줄 — 파티 "중"의 어색함, "후"의 흐지부지

**파티 참가자가 서로의 QR을 태그해 "만난 사람 수"를 쌓고, 기준 인원을 넘기면 증표를 받으며,
파티가 끝나면 만난 사람 중 다시 만나고 싶은 사람을 골라 서로 고른 쌍만 공개하는 웹.**

**현장 문제**: 축제·오프사이트·생일파티에서 아는 사람끼리만 논다. 처음 보는 사람에게 말 걸 계기가 없고, 파티가 끝나면 누구를 만났는지도, 누가 다시 보고 싶어 하는지도 남지 않는다.

### "만남"의 정의 (엔지니어 리뷰 반영)

**만남 = 상대의 4자리 코드를 손에 넣고(QR을 찍거나 직접 듣고) 내가 `지금 만났어요`를 누른 기록.** 자동으로 생기는 만남은 없다.
초대 링크에는 초대한 사람의 코드가 실리지만, 링크로 참여했다고 만남이 기록되지는 않는다 — 참여 직후 "초대한 OO님을 지금 만났나요?" 화면에서 **본인이 누를 때만** 기록된다. 원격으로 링크를 받은 사람은 이 버튼을 누르지 않으면 만남 0이다.
서버 규칙이 "상대 코드 없이는 만남 문서를 만들 수 없다"를 강제하므로, 참가자 목록만 보고 남을 태그하는 위조는 불가능하다(13절).

### 흐름 (전 · 중 · 후)

| 순간 | 동작 |
|---|---|
| 전 | 호스트 `파티 만들기` (파티 이름 · 내 이름 · 인원) → 호스트도 참가자 1번으로 등록, 초대 링크(= 호스트 QR과 같은 URL) |
| 중 | 참가자 링크로 `참여하기` → `참여 완료` + "초대한 OO님을 지금 만났나요?" → `지금 만났어요` → 만난 사람 1명 · `첫 만남` 증표. 이후 남의 QR을 **폰 기본 카메라**로 찍거나 `코드로 태그`에 4자리 입력 → 같은 확인 화면 → 둘 다 +1 → `K/N-1명 만남` 진행률 → 증표 → 미션 상대 |
| 후 | 호스트 `파티 종료`(또는 생성 24시간 경과) → 만난 사람 중 `다시 만나고 싶은 사람` 체크 → `선택 제출` → **서로 선택된 사람만** 표시 → `내 증표함`에 기록 → `다음 파티 만들기` |

### 증표 (발급 조건 고정 — "강제로 N명 이상")

| 증표 | 조건 |
|---|---|
| 첫 만남 | 1명 |
| 아이스브레이커 | 3명 |
| 파티 피플 | 참가자 절반 이상 |
| 파티 마스터 | 전원 |
| 미션 완료 | 지정된 미션 상대와 만남 |
| 재회 | 서로 선택된 사람 1명 이상 |

**분모 = 발급 시점의 현재 참가자 수.** 늦게 들어온 사람 때문에 **이미 받은 증표는 취소되지 않는다**(획득 시각 기록). 신고 인원(`size`)은 요금 계산에만 쓴다.

### 1:1 미션 (일대일 대응)

**참여 순서로 2명씩 짝을 짓는다: (1,2) (3,4) (5,6) …** 서로가 서로의 미션 상대(진짜 일대일 대응). 짝이 정해지면 새 참가자가 와도 **절대 바뀌지 않는다**. 홀수 번째로 마지막에 온 사람은 "다음 참가자가 오면 정해져요". 저장 없이 참가자 목록에서 계산.

> `ponytail:` 연달아 들어온 사람은 같이 온 친구일 수 있다 — 랜덤 짝은 서버 기록이 필요해서 뺐다. 호스트(1번)와 첫 참가자(2번)가 짝이 되므로 3단계 시나리오에서 `미션 완료` 증표도 함께 뜬다.

## 2. 초대/동반 참여 없이는 안 되는 이유 (B3)

남의 코드가 있어야 숫자가 오른다. 혼자면 0, 증표 0, 미션 없음. **전원이 동시에 각자** 진행한다(릴레이처럼 한 번에 한 명만 활동하는 구조가 아님).

**성장 루프**: 호스트 → 초대 링크 → 참여자 N명 → **참여자도 자기 코드가 실린 링크(= 내 QR)를 공유** — 데려온 사람이 `지금 만났어요`를 누르면 둘 다 +1 → 파티 후 `다음 파티 만들기`로 참여자가 다음 호스트가 된다. 공유 버튼이 아니라 **숫자가 오르는 유일한 경로**다.

3단계 시나리오의 2~3단계(초대 링크 복사 → 접속·참여·`지금 만났어요`·증표)가 그대로 B3 실동작 evidence다.

## 3. 대체재로 안 되는 이유 · 우리가 이기는 이유 (C3)

### 대체재 — 이름과 못 하는 지점

| 대체재 | 못 하는 지점 |
|---|---|
| 카카오톡 단톡방 · 구글폼 | "이 파티에서 만난 사람"이라는 데이터가 없다. 상호 선택은 **사람이 집계**해야 해서 짝사랑이 집계자에게 노출된다 |
| 인스타 맞팔 | 파티 밖 관계까지 섞인다. 진행률·증표·"다시 만나고 싶은 사람" 0 |
| **Event Passport PRO** (네이티브 앱) | 컨퍼런스·전시 **조직자용**: 조직자 계정 + 행사 사전 세팅 + 참가자 전원 앱 설치가 전제. 개인 QR 스캔 · 스탬프 · 진행도 · 보상은 있지만 **만남 기록에서 끝난다 — 파티 후 상호 선택 단계가 없다** |
| **Bumpt** (행사 네트워킹 게임화) | 퀘스트·수집품·어워드·행사 후 연결 유지. 역시 조직자 세팅형·영어권. **서로 고른 쌍만 공개하는 단계가 없다** |
| 종이 스탬프 랠리 | 부스용이지 사람용이 아니다. 사람마다 도장을 들고 다닐 수 없다 |

> ⬜ 제출 전 EPP 스토어 페이지·Bumpt 사이트를 열어 **설명 문구·요금(무료 인원, Pro 월 요금)·최근 업데이트 날짜**를 확인하고 그대로 인용한다. 리뷰 시점 확인값: EPP 무료 50명, Pro $100/월(200명). **다운로드 수 같은 검증 안 된 숫자는 쓰지 않는다.**

### 우리가 이기는 이유 — 솔직하게 둘로 나눈다

**① 결말이 다르다: 비밀 상호 선택.** EPP·Bumpt는 "몇 명 만났나"에서 끝난다. 파티 패스포트는 그중 **"누구와 다시 만나고 싶은가"를 서로 고른 쌍에게만** 돌려준다. 만남 기록은 이 결말의 재료다(만난 사람 중에서만 고를 수 있다).
이 비밀은 서버 코드 0줄로 **Firestore 규칙이 강제**한다(13절): 자기 선택만 · 한 번만(고른 뒤 취소 불가 → "골라 보고 빼기" 불가) · 만난 사람에게만 쓸 수 있고, **둘 다 골랐을 때만 읽힌다**. 목록 조회는 막혀 있어 개발자도 짝사랑을 못 본다. 단톡방·구글폼·EPP·Bumpt 어디에도 없는 단계다.

**② 세그먼트가 다르다: 세팅 0 · 설치 0 · 계정 0.** 생일·MT·오프사이트(10~50명)의 주최자는 행사 플랫폼을 세팅할 사람이 아니다. EPP의 무료 구간도 "조직자 사전 세팅 + 참가자 전원 앱 설치"가 조건이다. 우리는 링크 하나, 참가자는 이름만 친다.
**이건 해자가 아니라 우위다** — 경쟁사가 웹 온보딩을 붙이면 좁혀진다. 방어는 ①과, 참여자가 다음 호스트가 되는 루프(2절)로 한다. 문서에 "설치 0 = 방어력"이라고 쓰지 않는다.

## 4. 다시 올 이유 (B4)

- 증표는 파티가 끝나도 **`내 증표함`에 남고 다음 파티에서 누적**된다. 로그인이 없으므로 **같은 브라우저(폰)에 쌓인다** — 다음 파티에 같은 폰으로 참여하면 이어진다. 기기 간 이전은 안 된다(문서에 "계정으로 누적"이라고 쓰지 않는다).
- **트리거 시점**: 호스트가 `파티 종료`를 누른 직후(또는 생성 24시간 경과) 선택 화면 → 제출 → 결과 화면이 열린다. 상대가 아직 안 골랐으면 "상대가 제출하면 여기에 나타나요" — 다시 들어올 이유.
- 결과 화면 하단 `다음 파티 만들기` — 참여자가 다음 호스트가 되는 경로.

## 5. 타깃 고객 (B1) — ⬜ 제출 전 반드시 채운다

**관찰 인용이 없으면 6점 상한.** 아래 문장 틀에 오늘 안에 실명 수준 집단 + 답변 + 날짜를 넣는다.

```
⬜ <O월 O일> <OO대 OO동아리 회장 A / OO사 오프사이트 담당 B> 등 <N>명에게
   "처음 보는 사람이 많은 자리에서 말을 어떻게 트셨나요"를 물었더니
   "<직접 답변 인용>"이라고 답했다.
```

1차 타깃(셀 수 있는 집단): 대학 동아리·학과 신입 환영회 주최자, 50인 이상 기업의 오프사이트 담당자. "20대", "파티 하는 사람들" 같은 표현은 금지(3~4점).

## 6. 최초 유입 채널 (B2) — ⬜ 제출 전 반드시 채운다

**모수·주체·시점 중 둘이 없으면 5점 상한.** 채널 이름만 나열하면 4점.

```
⬜ <O월 O일> <팀원 이름>이 <에브리타임 OO대 게시판(일 활성 약 N명)>에 게시,
   <O월 O일> <OO 동아리연합회 단톡방(N명)>에 공유.
```

## 7. 수익 모델 (C1)

| 요소 | 값 |
|---|---|
| 지불 주체 | 파티 **호스트**(주최자) |
| 지불 시점 | **파티 생성 시**, 신고 인원 **51명 이상**일 때 |
| 금액 | **파티당 9,900원** (50명까지 무료) |

**가격 근거(기준점)**: 같은 인원대(51~200명)의 직접 경쟁사 Event Passport PRO는 **월 $100(약 14만 원)** 구독이다(⬜ 재확인). 생일·MT·오프사이트는 1회성이라 월 구독을 사지 않는다 — **1회 9,900원**은 그 공백이다. 50명 무료는 경쟁사 무료 구간과 같게 두되, 우리 무료 구간은 앱 설치·조직자 세팅이 없다.
⬜ B1 인터뷰 때 **"51명 이상 행사에 파티당 9,900원이면 낼 의향이 있나"를 같이 묻고 답변 수(N명 중 M명)를 적는다** — 이게 있어야 7점을 넘는다.

**화면에 반드시 노출**: 파티 생성 화면에 `50명까지 무료 / 51명부터 파티당 9,900원` 한 줄. 결제 연동은 불필요하지만 **문구가 화면에 없으면 C1은 6점 상한**이다.

## 8. 시장 규모 — 상향식 (C2)

계산식 없이 TAM만 인용하면 3점 상한. 유료 대상은 **51명 이상 행사**뿐이다 — 아래는 가정을 전부 표기한 상향식이며, 숫자는 작다. 성장 논리는 표 아래.

| 세그먼트 | 계산 | 연 매출 |
|---|---|---|
| 기업 오프사이트·워크숍 | 50인 이상 사업체 4만 곳「가정」× 연 2회 × 51명 이상 비율 50%「가정」× 전환 5%「가정」= 2,000건 × 9,900원 | **약 2,000만 원** |
| 대학 학과·동아리연합 행사 | 대학 400곳「가정」× 51명 이상 행사 연 20건「가정」× 전환 10%「가정」= 800건 × 9,900원 | **약 800만 원** |
| **합계** | | **약 2,800만 원/년** |

⬜ 제출 전 「가정」 중 사업체 수·대학 수는 통계 출처를 붙인다.

**성장 논리(단가·모수 확장)**: ① 참여자 → 다음 호스트 루프로 무료 파티가 모수를 키운다(50명 이하 파티는 전부 무료 유입 채널) ② 축제·페스티벌 단위 **스폰서 증표**(증표에 주최·스폰서 이름, 행사당 단가 10배) ③ 행사 대행사 B2B. ②③은 미구현이므로 기획안에서는 "확장 경로"로만 쓴다.

## 9. 단위 경제성 (C4) — 숫자

파티 1건 = 20명 · 2시간 · 만남 40건 · 선택 30건「가정」, `onSnapshot` 구독 + 규칙 검증 읽기 포함.

| 항목 | 수치 |
|---|---|
| 문서 쓰기 | 약 110건 → $0.18/10만 → **0.3원** |
| 문서 읽기 (구독 + 규칙 `get()` + 결과 확인) | 약 5,000건 → $0.06/10만 → **4원** |
| 호스팅 | GitHub Pages **0원** |
| **파티 1건당 서버 원가** | **약 5원** (환율 1,400원/$「가정」) |
| 무료 티어 소화량 | 5만 reads/일 ÷ 5,000 ≈ **하루 10파티까지 0원** |
| 운영 인력 | **0명** — 생성·초대·태그·증표·종료·선택·결과 전부 자동, 서버 코드 0줄 |

**유료 파티 1건 기여이익 ≈ 9,900 − 결제 수수료 약 330원(3.3%「가정」) − 서버 5원 ≈ 9,565원.** 이건 **서버 원가 기준**이다 — CS·마케팅·세금은 포함하지 않았다("마진 99.9%"라고 쓰지 않는다).

**폴링을 쓰지 않는 이유(숫자)**: 3초 폴링이면 20명 파티에서 1,200 reads/3초 → 무료 티어 5만 reads가 **약 2분에 소진**되고 화면이 멈춘다(A1·A2 즉사). `onSnapshot`은 바뀐 문서만 과금된다. 예외: 파티 후 결과 확인은 규칙상 구독이 불가능해(양쪽이 고르기 전엔 읽기 거부) **30초 간격 · 내가 고른 사람만** 확인한다.

## 10. 제출 3단계 시나리오 (submission-guide 형식)

```
1단계 — 첫 화면에서 "파티 만들기" 버튼을 누르고 "파티 이름"에 "금요일 파티", "내 이름"에 "지훈"을 입력한 뒤 "파티 만들기"를 누른다. "초대 링크가 생성되었습니다"가 보이고 주소가 /party/로 바뀌면 성공
2단계 — "초대 링크 복사" 버튼을 누른다. "복사되었습니다"가 보이고 화면에 초대 링크(URL)가 표시되면 성공
3단계 — 표시된 초대 링크로 접속해 "이름"에 "김서준"을 입력하고 "참여하기"를 누른 뒤 "지금 만났어요"를 누른다. "만난 사람 1명"과 "첫 만남" 증표가 보이면 성공
```

**3단계에서 에이전트가 하는 추가 동작은 클릭 1번(`지금 만났어요`)이다.** 이 클릭이 있어야 만남이 기록되므로 "링크 = 만남"이 아니라 **본인 확인**이 evidence에 남는다. 그 결과로 만난 사람 수·`첫 만남`·`미션 완료` 증표가 화면에 뜨고 B3·B4·C3·D가 6점 상한에서 풀린다.

**같은 브라우저에서 호스트와 김서준을 연달아 해도 성립한다** — 심사 에이전트는 탭 하나로 3단계를 돌릴 가능성이 높다. 초대 링크는 항상 참여 폼을 보여주고, 한 브라우저가 여러 참가자를 가질 수 있게 설계했다(PRD 참조).

**파티 종료·상호 선택 화면은 시나리오에 넣지 않는다.** 단계가 무거워질수록 실패 확률만 오른다. 심사 에이전트가 A3(기획안 대비 구현)를 확인할 수 있게 태그는 **`코드로 태그` 4자리 입력**으로도 동작한다 — Playwright는 카메라로 QR을 못 찍는다.

### 화면 텍스트 (글자 단위 고정)
`파티 만들기` · `파티 이름` · `내 이름` · `인원` · `초대 링크가 생성되었습니다` · `초대 링크 복사` · `복사되었습니다` · `이름` · `참여하기` · `참여 완료` · `지금 만났어요` · `만난 사람` · `첫 만남` · `내 코드` · `코드로 태그` · `태그` · `미션 상대` · `파티 종료` · `다시 만나고 싶은 사람` · `선택 제출` · `서로 선택된 사람` · `다시 확인` · `다음 파티 만들기` · `내 증표함`

## 11. 구현 규칙 (엔지니어 페르소나 대비)

| # | 함정 | 처리 |
|---|---|---|
| 1 | 클립보드가 2단계를 죽인다 — `navigator.clipboard.writeText`는 문서에 포커스가 없으면 reject | `try/catch` → 실패 시 `execCommand('copy')` 폴백 → 그래도 실패하면 URL 텍스트를 선택 상태로 노출하고 "링크를 길게 눌러 복사해 주세요". **성공 문구를 거짓으로 띄우지 않는다** |
| 2 | 폰 기본 카메라가 **다른 브라우저**로 URL을 연다 (카톡 인앱 → Safari) → 그 브라우저엔 내 신원이 없음 | 확인 화면이 "OO님의 코드는 AB12 — 참여한 브라우저의 `코드로 태그`에 입력하세요"를 보여준다. 신원 이전 없음 |
| 3 | 4자리 코드 충돌 | 코드 문서는 `create`만 허용 → 이미 있으면 실패 → 재발급. 원자적 유일성 |
| 4 | 자기 자신 태그·중복 태그·남 대신 태그 | 문서 ID = 정렬된 쌍 `a_b`, 규칙이 `a < b`·**상대 코드 일치**·요청자가 쌍의 일원인지 검사 |
| 5 | 24시간 자동 종료에 Cloud Functions를 쓰면 **유료 플랜** | 서버 작업 없이 클라이언트와 규칙이 `createdAt + 24h`로 판정 |
| 6 | 익명 인증 실패(네트워크) | 첫 화면 대신 "연결에 실패했어요 · 다시 시도" — 조용히 죽지 않는다 |
| 7 | 새 탭·`alert`·`confirm`·호버 메뉴 | 0건 |
| 8 | 모바일 375px · 콘솔 에러 | 에러 0, 가로 스크롤 0, 빈 상태·잘못된 초대 링크·종료된 파티 안내 화면 |

## 12. 남은 시간에 완주 가능한가

| 시각 | 마일스톤 |
|---|---|
| +0:10 | Firebase 프로젝트 + 익명 인증 켜기 + 규칙 붙여넣기 (문서 담당) · 빈 페이지 배포 확인 |
| +0:50 | 1~3단계 동작 (생성·호스트 등록 · 초대 링크 복사 · 참여 · `지금 만났어요` · 만난 사람 수 · `첫 만남`) — **A1은 여기서 끝남** |
| +1:20 | QR · `코드로 태그` · 진행률 · 나머지 증표 · 미션 상대 · 요금 안내 한 줄 |
| +1:45 | 파티 종료 · 다시 만나고 싶은 사람 · 서로 선택된 사람 · 내 증표함 |
| +2:00 | 빈/에러 상태, 모바일 375px, 콘솔 에러 0 |
| +2:10 | Playwright로 배포 URL 3단계 검증 → 배포 프리즈 |

- 서버 코드 0줄. 백엔드 = Firestore 컬렉션 5개 + 규칙 파일 1개 + 익명 인증 토글.
- QR = URL 한 줄 + `qrcode.react` 컴포넌트 하나. 인앱 스캐너 없음.
- **시간이 밀리면 "파티 후"부터 자른다.** 태그·증표까지만으로도 B3·B4·D 성립. 문서에는 배포에서 동작 확인된 기능만 쓴다.

## 13. 저장소 · 보안 규칙 — 무엇을 강제하고 무엇은 못 하는가

Firebase Firestore + **익명 인증**(`signInAnonymously`, 화면에 로그인 없음). 브라우저마다 uid가 하나 생기고, 규칙은 이 uid로 "내 것"을 판정한다. 상세와 규칙 전문은 [backend PRD](../prd/backend.md).

```
parties/{id}                     { name, size, hostUid, createdAt, endedAt }
parties/{id}/participants/{pid}  { name, uid, joinedAt }
parties/{id}/codes/{code}        { pid }                 // get만 허용 · list 금지 → 코드를 아는 사람만 조회
parties/{id}/meets/{a_b}         { a, b, code, at }      // code = 상대 코드, 규칙이 대조
parties/{id}/picks/{a_b}         { [pid]: true }         // 자기 키만 · 한 번만 · 만난 쌍만 · 둘 다 있을 때만 읽힘
```

| 규칙이 **강제**하는 것 | 규칙이 **못 하는** 것(솔직하게) |
|---|---|
| 만남 문서는 **상대 코드가 맞아야** 생성 — 참가자 목록만 보고 남을 태그할 수 없다 | 코드를 받은 뒤 실제로 대화했는지는 검증 못 한다(자기 확인). 증표는 금전 가치가 없어 위조 유인이 낮다 |
| 종료된 파티에는 만남을 쓸 수 없다 | 원격으로 받은 링크에도 코드가 실린다 — 그래서 자동 기록 대신 `지금 만났어요` 확인을 둔다 |
| 선택은 **자기 키만**, **한 번만**(취소·수정 불가 → 골라 보고 빼기 불가), **만난 쌍에만**, **종료 후에만** | 한 브라우저가 참가자 둘을 가지면(심사 에이전트 케이스) 그 둘끼리는 스스로 상호 선택을 만들 수 있다 — 실사용에선 자기 자신과의 매칭일 뿐 |
| 결과는 **둘 다 골랐을 때만** `get` 허용, `list` 금지 → 개발자·운영자·devtools 모두 짝사랑을 못 본다 | 증표함은 브라우저 저장소 — 폰을 바꾸면 이어지지 않는다 |

> 자가 채점표는 의도적으로 뺐다. 점수 판정은 이 명세를 입력으로 **별도 세션에서 [personas](../personas/) 3종 검증**을 돌린다.
> 남은 ⬜ 6개(B1 인터뷰 인용 · B2 커뮤니티 모수/주체/날짜 · C1 지불 의사 응답 수 · C2 사업체·대학 수 출처 · EPP/Bumpt 문구·요금 재확인)는 코드보다 먼저 채운다 — B·C의 30%가 여기 걸려 있다.
