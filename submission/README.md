# 심사 제출물 — 이 폴더가 제출 확정본이다

제출 페이지의 각 입력란에 어떤 파일을 넣는지, 넣기 전에 무엇을 확인하는지 정리한다.
채점 기준은 [docs/judging-criteria.md](../docs/judging-criteria.md), 폼 실물 규격은 [docs/submission-guide.md](../docs/submission-guide.md)에 있다.

## 1. 폼 필드 ↔ 파일 매핑

| # | 제출 폼 필드 | 필수 | 제한 | 넣을 파일 |
|---|---|---|---|---|
| 1 | 팀 이름 | 필수 | 60자 | [01-팀정보.md](./01-팀정보.md) §1 |
| 2 | 서비스 URL | 필수 | URL | [01-팀정보.md](./01-팀정보.md) §2 |
| 3·4 | 테스트 계정 | 선택 | — | [01-팀정보.md](./01-팀정보.md) §3 — **비운다** |
| 5 | 핵심 플로우 3단계 | 필수 | 한 줄 × 3 | [02-핵심플로우-3단계.md](./02-핵심플로우-3단계.md) §1~3 |
| 6 | 기획안 | 필수 | markdown 8,000자 | [03-기획안.md](./03-기획안.md) 전문 |
| 7 | 발표 스크립트 | 필수 | markdown 4,000자 | [04-발표스크립트.md](./04-발표스크립트.md) 전문 |
| 8 | 발표자료 | 선택 | HTML 400,000자 | [05-발표자료.html](./05-발표자료.html) 전문 |
| 9 | 확인 체크박스 | 필수 | — | 팀원 전원 확인 후 체크 |

`_template/제출페이지-스냅샷.html`은 폼 실물 저장본(필드·글자 수 제한 확인용)이고, `_verify/`는 페르소나 자가 채점 결과다. 둘 다 제출물이 아니다.

## 2. 글자 수 확인

폼은 문자 수로 센다. 붙여넣기 전에 확인한다.

```bash
wc -m submission/03-기획안.md submission/04-발표스크립트.md
wc -c submission/05-발표자료.html
```

기준: 기획안 ≤ 8,000자 · 스크립트 ≤ 4,000자 · 발표자료 ≤ 400,000자.

## 3. 제출 직전 체크리스트

**서비스**

- [ ] 시크릿 창에서 배포 URL을 열어 3단계를 손으로 완주 (데스크톱)
- [ ] 모바일 뷰포트(375×812)에서도 완주, 레이아웃 깨짐 없음
- [ ] 두 뷰포트 모두 콘솔 에러 0건
- [ ] 첫 화면이 로그인 없이 1단계를 시작할 수 있는 상태
- [ ] 배포 프리즈 — 제출 후 서비스 URL·배포 내용을 바꾸지 않는다

**문서**

- [ ] 3단계 문장의 따옴표 문구가 화면 텍스트와 글자 단위로 일치 ([02 §4 대조표](./02-핵심플로우-3단계.md))
- [ ] 기획안·스크립트·발표자료의 숫자·인명·금액이 서로 어긋나지 않음 (§4 참조)
- [ ] 문서에 쓴 기능이 전부 배포된 앱에서 동작 (미구현 기능을 근거로 쓰면 해당 항목 6점 상한)
- [ ] "~할 계획이다/예정이다" 같은 계획형 문장 없음 (근거가 아니라 의도로 읽혀 5점 상한)

**제출**

- [ ] 팀 이름 오타 확인 — 확정 후 변경 불가
- [ ] 팀원 전원이 이 체크리스트를 함께 확인
- [ ] 한 명만 "제출하고 심사 시작"을 누른다 — **1회 제출, 수정 불가**

## 4. 세 문서에 공통으로 실리는 숫자

기획안·스크립트·발표자료가 서로 다른 값을 말하면 구현 대조와 무관하게 신뢰도가 깎인다. 아래 값은 **한 글자도 다르지 않게** 유지한다.

| 가격 | 20명까지 무료 / 초과 시 파티당 9,900원 |

| B2 시점 | 2026-09-01 · 2026-09-02 |
